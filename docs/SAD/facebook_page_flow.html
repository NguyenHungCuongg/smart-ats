Khái niệm & Ràng buộc

1. Kiến trúc phân quyền & Ràng buộc Đồ án

Tính năng phát tán tin tuyển dụng (FR-A3.5) cho phép Recruiter phát bài đăng trực tiếp lên Facebook Page của công ty kèm Public Apply Link. Dưới đây là các cấu hình then chốt đã thống nhất trong SRS & SAD.

📌 Ràng buộc Meta App (SRS §5)

  • Development Mode: Do đồ án khóa luận không có tư cách pháp nhân (Business Verification), Meta App giữ ở chế độ Development Mode.
  • Giới hạn đối tượng: Chỉ người dùng có role trong App (Admin / Developer / Tester) mới được ủy quyền Page và nhìn thấy bài đăng test qua API.
  • Permissions: pages_show_list, pages_read_engagement, pages_manage_posts.

🔒 Nguyên tắc Bảo mật Token (SAD §5.6, NFR-SEC-10)

  • Không lưu User Token: User Access Token chỉ dùng tạm trong request để lấy Page Token rồi hủy ngay.
  • Mã hóa Fernet: Page Access Token được mã hóa đối xứng bằng khóa bí mật CHANNEL_TOKEN_KEY trước khi lưu DB.
  • Không lọt Client: Token không bao giờ trả về frontend, không ghi vào logs hay Audit Logs.

Luồng OAuth 2.0

2. Luồng Kết nối Facebook Page (Dành cho Company Admin)

Company Admin thực hiện kết nối Fanpage của doanh nghiệp vào Workspace. Luồng trao đổi token từ ngắn hạn sang dài hạn và mã hóa Page Access Token vĩnh viễn (never-expiring).

💡 Điểm tinh hoa của Graph API: Khi bạn lấy Page Access Token từ một Long-lived User Token, Page Access Token nhận được là vĩnh viễn (never expires)! Bạn không cần cơ chế refresh token định kỳ, token chỉ hết hạn nếu Admin chủ động đổi mật khẩu Facebook hoặc thu hồi quyền.

3. Luồng Đăng tin Job Ad lên Facebook Page (Dành cho Recruiter)

Recruiter bấm phát tán tin tuyển dụng của một Job đã duyệt. Quy trình thực hiện khóa giao dịch để đảm bảo tính Idempotency (không bao giờ đăng 2 bài cho cùng 1 Job lên Page).

Hai thực thể chịu trách nhiệm cho kênh kết nối và lịch sử bài đăng. Cả hai đều thuộc phạm vi bảo vệ của RLS theo tenant_id.

Xử lý Ngoại lệ

5. Cơ chế Xử lý Ngoại lệ & Thu hồi Quyền

❌ Lỗi Token bị thu hồi (Meta Error Code 190)

Xảy ra khi Admin đổi mật khẩu Facebook, xóa quyền của App trong Cài đặt cá nhân, hoặc App bị gỡ.

  • Graph API trả HTTP 400 kèm mã lỗi con error.code == 190.
  • FastAPI bắt ngoại lệ này, không tạo record trong channel_posts.
  • API phản hồi với mã lỗi miền CHANNEL_TOKEN_INVALID.
  • Frontend hiển thị banner đề nghị Company Admin vào /settings/channels kết nối lại.

🌐 Thẻ Open Graph & Public Apply Link (SAD §5.6)

Khi đăng bài lên Facebook kèm link, Facebook Crawler sẽ cào trang Public Apply Link:

  • Trang /apply/{slug} là server component trả sẵn thẻ Open Graph (og:title, og:description, og:image).
  • Kèm schema JSON-LD JobPosting cho Google for Jobs.
  • Nhờ đó, bài đăng trên Facebook hiển thị thumbnail xem trước cực kỳ chuyên nghiệp mà không cần upload ảnh thủ công qua API.
apps/api/app/channels.py · Logic mẫu gọi Meta Graph API Python 3.13 
import httpx
from cryptography.fernet import Fernet
from app.config import settings

def publish_job_to_facebook_page(
    page_id: str,
    token_ciphertext: bytes,
    job_ad_text: str,
    apply_url: str
) -> dict[str, str]:
    # 1. Giải mã token bằng Fernet
    fernet = Fernet(settings.CHANNEL_TOKEN_KEY.encode())
    page_token = fernet.decrypt(token_ciphertext).decode()

    # 2. Gọi đồng bộ tới Meta Graph API v26.0
    url = f"https://graph.facebook.com/v26.0/{page_id}/feed"
    payload = {
        "message": job_ad_text,
        "link": apply_url,
        "access_token": page_token
    }

    resp = httpx.post(url, json=payload, timeout=10.0)
    data = resp.json()

    if resp.status_code != 200:
        error_code = data.get("error", {}).get("code")
        if error_code == 190:
            raise ChannelTokenExpiredException("Facebook Page token invalid or revoked")
        raise ChannelPublishException(f"Meta Graph API error: {data.get('error', {}).get('message')}")

    post_id = data["id"]
    return {
        "external_post_id": post_id,
        "url": f"https://www.facebook.com/{post_id}"
    }
