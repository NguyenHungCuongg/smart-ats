## 1. Database Strategy

- **PostgreSQL 18** with the **pgvector 0.8** extension, one shared schema (`public`).
- **Forced Row-Level Security** on every tenant-owned table (ADR-0001). The single policy on each table is:
  ```sql
  USING      (tenant_id = NULLIF(current_setting('app.current_tenant_id', true), '')::uuid)
  WITH CHECK (tenant_id = NULLIF(current_setting('app.current_tenant_id', true), '')::uuid)
  ```
- **Roles:** `ats_owner` owns every table and runs migrations. `ats_app` is used by the API and the workers; it has DML privileges only, without `BYPASSRLS`.
- **Conventions:**
  - Primary keys are `uuid`, generated by `uuidv7()` (native in PostgreSQL 18, time-ordered and index-friendly).
  - Timestamps are `timestamptz`.
  - Enums are `text` with `CHECK` constraints, which are easier to migrate than `CREATE TYPE`.
  - Every tenant-owned table has `tenant_id uuid NOT NULL REFERENCES tenants(id)` and a composite index leading with `tenant_id`.
  - Foreign keys between tenant tables are composite `(tenant_id, id)`. The database therefore rejects a row that references another tenant's row, even when the application sets the wrong id.

Legend used below: **PK** primary key · **FK** foreign key · **UQ** unique · **NN** not null · **RLS** forced row-level security.

## 8. Pre-tenant `SECURITY DEFINER` functions

Owned by `ats_owner`. `ats_app` has `EXECUTE` only. Each returns the minimum columns needed.

| Function | Returns | Used by |
|---|---|---|
| `auth_find_user(email)` | id, tenant_id, role, password_hash, is_active, locked_until | Login |
| `auth_find_user_by_google_sub(sub)` | same | Google login |
| `public_job_by_slug(slug)` | tenant_id, job_id, title, status, apply_deadline, tenant name/logo/privacy URL | Public Apply Link |
| `accept_invitation(token_hash)` | tenant_id, email, role (and marks it accepted) | Invitation acceptance |

## 9. Key Indexes

- `(tenant_id, …)` leading index on every tenant table.
- `applications (tenant_id, job_id, stage)` for the Kanban board.
- `score_results UNIQUE (scoring_run_id, application_id)`.
- `cv_documents UNIQUE (tenant_id, sha256)` and HNSW on `embedding vector_cosine_ops`.
- `candidates UNIQUE (tenant_id, email) WHERE email IS NOT NULL`.
- `ai_usage_entries (tenant_id, created_at)`.
- `jobs UNIQUE (public_slug)`.

## 10. Changes from v3.0

| v3.0 | v3.1 | Why |
|---|---|---|
| `pipeline_stages` held both current state and history | `applications.stage` + `application_stage_history` | Current stage in O(1); history append-only; optimistic locking |
| `job_postings` | `jobs` | Glossary (`CONTEXT.md`) |
| `candidates.parsed_cv`, `raw_cv_url` | `cv_documents` (1 Candidate : N CV Documents) | Re-application, deduplication, embedding per CV |
| `scoring_sessions` / `scoring_results` without `tenant_id` | `scoring_runs` / `score_results`, both with `tenant_id` and version stamps | No "RLS via JOIN"; reproducibility |
| `campaigns.planned_steps` / `reflection_log` JSONB, `campaign_candidates` | `campaign_events` + `campaign_proposals` + LangGraph checkpointer | Append-only trace; durable Checkpoint |
| `confidence_scores` (LLM self-reported) | `field_verification` | Verified against the source text |
| — | `refresh_tokens`, `invitations`, `job_reviewers`, `upload_batches(_items)`, `interview_question_sets`, `comment_mentions`, `notifications`, `email_messages`, `ai_usage_entries`, `audit_logs`, `platform_audit_logs` | Required by SRS features that had no storage |
