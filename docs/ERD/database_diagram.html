Smart ATS data model

Companion diagrams for docs/ERD/entity_relationship_diagram.md, which holds every column, constraint and index. Only key fields are drawn. Every tenant-owned entity also carries tenant_id (not drawn) under forced row-level security, and foreign keys between tenant tables are composite (tenant_id, id) (ADR-0001). tstz = timestamptz.

Figure A · ER

Recruitment core

An Application is one Candidate considered for one Job (unique on job + candidate) and carries the current Stage; history is append-only. A Candidate may have several CV Documents (deduplicated by SHA-256 per tenant); each Application is evaluated on one of them. Upload items fail or succeed independently.

Figure B · ER

Evaluation and agent

A Scoring Run freezes weights, criteria, model, prompt and rubric versions. score_results is unique on (scoring_run_id, application_id) — the idempotency key for retried tasks. A Campaign’s id is its LangGraph thread_id; LangGraph’s own checkpoint tables are not drawn and sit outside RLS.

Figure C · ER

Tenancy, identity and ledgers

tenants is a platform table without RLS. users.tenant_id is null only for System Admins. Refresh tokens rotate within a family; reusing a rotated token revokes the family. Login, Public Apply and invitation acceptance resolve the tenant through SECURITY DEFINER functions.

Figure D · ER

Collaboration and communication

Comments are soft-deleted. email_messages doubles as the outbox: a row is written as QUEUED in the business transaction and its id is the provider idempotency key.
